# Отчётность — кейс 3

Отчёты ниже рассчитаны по исходному payments.csv за ноябрь 2025 года. Денежные показатели чаевых учитывают только SUCCESS: отказ не приносит дохода. payments_count считает все попытки в выбранном разрезе, success_rate — долю успешных среди всех. avg_tip_pct — невзвешенное среднее процентов успешных платежей. Средние округляются до двух знаков HALF_UP, success_rate — до четырёх.

Даты from/to включаются целиком в UTC: от начала from до начала дня после to. Период примеров — 2025-11-01…2025-11-30. При отсутствии попыток: payments_count=0, tips_total=0, средние и success_rate=null; при отсутствии успехов средние и top_day=null.

Мерчант видит своё заведение, официант — только свой личный отчёт, администратор — служебные отчёты. Клиент доступа не имеет. Параметр запроса не заменяет серверную проверку прав.

Следующий исходный образец оставлен без изменения. Его 550.00 и 4 платежа условны и не совпадают с текущим CSV; фактический расчёт приведён после него. В исходном блоке также сохранено экранирование подчёркиваний: его нельзя копировать как готовый JSON. Новые примеры ниже используют корректные имена полей без этого экранирования.
## 1\. Отчёт по мерчанту (ОБРАЗЕЦ)

**Endpoint:** `GET /api/v1/reports/tips?merchant\_id=m\_001\&from=2025-11-01\&to=2025-11-30`

**Метрики:**

|Метрика|Формула|Пример|
|-|-|-|
|tips\_total|sum(tip)|550.00|
|payments\_count|count(payments)|4|
|avg\_tip\_pct|avg(tip / amount × 100)|10.0|
|success\_rate|count(SUCCESS) / count(\*)|0.75|

**Пример ответа:**

```json
{
  "merchant\_id": "m\_001",
  "period": "2025-11",
  "tips\_total": 550.00,
  "payments\_count": 4,
  "avg\_tip\_pct": 10.0,
  "success\_rate": 0.75
}
```

## 1.1. Фактический отчёт m_001

Для того же endpoint из образца в CSV найдено 6 платежей, из них 5 SUCCESS и 1 DECLINED. Чаевые успешных: 31.85 + 77.40 + 136.65 + 51.75 + 117.20 = 414.85. Чаевые отказа p_0057 (196.35) не включаются. Средний процент: (5 + 10 + 15 + 5 + 10) / 5 = 9.00. Доля успеха: 5 / 6 = 0.8333.

```json
{
  "merchant_id": "m_001",
  "period": "2025-11",
  "tips_total": 414.85,
  "payments_count": 6,
  "avg_tip_pct": 9.00,
  "success_rate": 0.8333
}
```

## 2. Отчёт по официанту

**Endpoint:** `GET /api/v1/reports/tips?employee_id=e_001&from=2025-11-01&to=2025-11-30`

Для личного разреза employee_id заменяет merchant_id в фильтре; сервер дополнительно ограничивает доступ ролью пользователя. Это соответствует личному отчёту исходного раздела 2; YAML заполнен и допускает один из фильтров merchant_id/employee_id.

| Метрика | Формула | Пример e_001 |
|---|---|---|
| tips_total | sum(tip) по SUCCESS сотрудника за период | 83.60 |
| payments_count | count всех попыток сотрудника за период | 2 |
| avg_tip_amount | sum(tip SUCCESS) / count(SUCCESS) | 41.80 |
| top_day | день UTC с максимальной суммой tip по SUCCESS; при равенстве — более ранний | 2025-11-03 |

Входные записи: p_0001 — 31.85 за 1 ноября, p_0055 — 51.75 за 3 ноября; обе SUCCESS. Итого 83.60 / 2 = 41.80.

```json
{
  "employee_id": "e_001",
  "period": "2025-11",
  "tips_total": 83.60,
  "payments_count": 2,
  "avg_tip_amount": 41.80,
  "top_day": "2025-11-03"
}
```

## 3. Отчёт по дням

**Endpoint:** `GET /api/v1/reports/tips/daily?merchant_id=m_001&from=2025-11-01&to=2025-11-30`

| Метрика | Формула | Пример 2025-11-01 |
|---|---|---|
| date | дата UTC из timestamp | 2025-11-01 |
| tips_total | sum(tip) по SUCCESS за день | 245.90 |
| payments_count | count всех попыток за день | 3 |
| avg_tip_pct | avg(tip / amount × 100) по SUCCESS за день | 10.00 |

Возвращаются дни с хотя бы одной попыткой в порядке даты. 1 ноября: 31.85 + 77.40 + 136.65 = 245.90; 3 ноября: 51.75 + 117.20 = 168.95, отказ не включён в сумму и средний процент, но включён в число попыток.

```json
{
  "merchant_id": "m_001",
  "daily": [
    {"date": "2025-11-01", "tips_total": 245.90, "payments_count": 3, "avg_tip_pct": 10.00},
    {"date": "2025-11-03", "tips_total": 168.95, "payments_count": 3, "avg_tip_pct": 7.50}
  ]
}
```

Контроль: 245.90 + 168.95 = 414.85; 3 + 3 = 6. Средний процент мерчанта вычисляется по отдельным успешным платежам, а не как простое среднее дневных процентов.
