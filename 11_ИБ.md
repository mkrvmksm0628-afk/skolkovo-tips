# Информационная безопасность — кейс 3 «Онлайн-чаевые»

Ниже проектные меры для учебной платформы. Это описание требований; оно не подтверждает их реализацию в имеющемся прототипе.

## 1. Модель угроз

| ID | Угроза | Актив | Вероятность | Ущерб | Источник |
|---|---|---|---|---|---|
| U-1 | Подделка QR | деньги клиента | средняя | высокий | злоумышленник |
| U-2 | Повторное использование QR (replay) | деньги клиента | средняя | средний | перехват |
| U-3 | Кража реквизитов официанта | реквизиты выплат, конфиденциальность | средняя | высокий | утечка CSV, логов или лишние права |
| U-4 | Двойное списание при повторе | деньги клиента, целостность платежей | высокая | высокий | повтор нажатия, сетевой повтор, параллельные запросы |
| U-5 | Подмена суммы или получателя | деньги клиента, корректность чека | средняя | высокий | недобросовестный сотрудник или изменение запроса |
| U-6 | Отсутствие или подмена аудита | история операций, возможность разбора споров | средняя | высокий | ошибка программы или сотрудник с лишним доступом |

Оценки качественные, для учебного анализа; статистических измерений не проводилось.

## 2. Меры защиты

| ID | Угроза | Мера | Остаточный риск |
|---|---|---|---|
| U-1 | подделка QR | HMAC-SHA256 + секрет | низкий |
| U-2 | replay | nonce + TTL 24 ч | низкий |
| U-3 | Кража реквизитов | Только маска ****NNNN; PAN/CVV не принимаются; права по ролям, маскирование логов | низкий при соблюдении мер; маска остаётся служебной информацией |
| U-4 | Двойное списание | Ключ идемпотентности, единичное подтверждение, атомарный резерв QR; после TIMEOUT проверка прежнего payment_id | низкий при согласованном хранении; один append в CSV гарантий не даёт |
| U-5 | Подмена суммы или получателя | Подписанная связь с чеком и официантом, контроль принадлежности; суммы из доверенной системы чеков, пересчёт на сервере и подтверждение клиентом | средний в учебном режиме: base_amount приходит извне, подпись QR сумму не покрывает |
| U-6 | Отсутствие/подмена аудита | Запись события вместе с переходом, журнал только на добавление, ограничение прав на удаление, резервное копирование | низкий при контроле доступа к хранилищу |

Меры U-1/U-2 из исходного образца сохранены. TTL сам по себе не предотвращает повтор внутри 24 часов; нужен учёт резерва/использования QR. Передача данных в проекте — по HTTPS; ограничение частоты запросов указано в 04_requirements.md. Ссылка на QR не должна попадать в общедоступные логи.

## 3. RBAC — матрица прав

| Действие | Мерчант | Официант | Клиент | Администратор |
|---|---|---|---|---|
| Регистрация | да | по приглашению мерчанта | необязательна, анонимная сессия | назначается владельцем платформы |
| Генерация QR | да, своё заведение | свои чеки своего мерчанта | нет | нет |
| Просмотр своих чаевых | да | только свои | нет | служебный доступ к отчётам |
| Сканирование QR | нет | нет | свой чек | нет |
| Оплата чаевых | нет | нет | да | нет |
| Просмотр отчёта | только своё заведение | только личный; отчёт заведения закрыт | нет | служебные задачи |
| Блокировка мерчанта | нет | нет | нет | да |
| Изменение справочников | свои данные и сотрудники, без активации | нет | нет | да, с аудитом |

Матрица согласована с 02_roles.md. Роль и принадлежность объекта проверяются на сервере, а не только скрытием кнопок.

## 4. Аудит — структура события

| Поле | Тип | Пример | Зачем |
|---|---|---|---|
| event_id | string | evt_0001 | уникальный ID |
| payment_id | string/null | p_0001 | привязка к платежу; null до его создания |
| qr_id | string/null | qr_001 | связь с QR; null для неизвестного QR |
| action | enum | payment_created | тип действия |
| from_status | enum/null | null | состояние до создания; для перехода — прежний статус |
| to_status | enum/null | CREATED | состояние после события; null при отказе до создания |
| amount_total | decimal/null | 668.85 | проверяемая сумма без карточных данных |
| actor | string | client:session_demo | роль и служебный идентификатор инициатора |
| at | datetime UTC | 2025-11-01T18:00:00Z | момент события |
| error_code | string/null | null | причина ошибки, если она была |

В строках приведён согласованный пример создания платежа; это иллюстрация, а не полученный лог. Для отказа шлюза action=payment_declined, from_status=PENDING, to_status=DECLINED, error_code=CARD_DECLINED. Для таймаута from_status=to_status=PENDING, action=gateway_timeout. Секреты и токены в события не записываются. Полная модель и допустимые значения — в 08_errors.md.

## 5. Защита данных

**Нельзя хранить:**

- PAN (полный номер карты) и CVV клиента — платформа их не принимает; реальная оплата вне учебного прототипа передавалась бы провайдеру.
- Полные реквизиты официанта — не сохраняются ни в CSV, ни в логах. Для задания достаточно маски; реальные выплаты требуют отдельного провайдера и не выполняются.

**Можно хранить:**

- payment_details — только маска `****NNNN`.
- signature — 16 hex для проверки QR; это не HMAC-ключ. QR-ссылку с подписью не публиковать.
- nonce — 6 hex вместе с QR и учётом его использования; значение не заменяет контроль сессии и идемпотентности.

Маскирование на синтетическом примере, до записи в журнал:

```text
До обработки: employee_id=e_001 payment_details=<полный номер из внешнего провайдера> confirm_token=<токен>
В журнале:    employee_id=e_001 payment_details=****1001 confirm_token=[REDACTED]
```

Строка «до» поясняет преобразование и сама в журнал не сохраняется. В учебной системе вводится уже готовая маска.

## 6. Секреты и ключи

| Секрет | Где хранится | Кто имеет доступ | Ротация |
|---|---|---|---|
| HMAC-ключ | защищённая конфигурация среды, передаётся процессу как HMAC_SECRET через окружение | сервис подписи/проверки и уполномоченный оператор | срок в задании не задан; порядок замены должен учитывать подписи уже выпущенных QR |
| Пароль БД | защищённая конфигурация, процесс читает DB_PASSWORD из окружения | сервис хранения и уполномоченный оператор | срок в задании не задан; в учебном SQLite пароль БД не используется |

Правила: секреты не в Git, не логируются, приложение читает их только через os.environ. Смена HMAC-ключа влияет на выпущенные QR: это нужно учитывать, а не просто заменять строку. Базы данных в текущем CSV-прототипе нет; пароль БД — требование на случай её появления.

**Состояние реализации:** 04_прототип.py читает ключ только из HMAC_SECRET; значение ключа отсутствует в исходнике Python. Для выданного набора используется общеизвестное учебное значение из исходного задания (см. README). Это не производственный секрет. SQLite — локальный файл без отдельного пароля; защита файла зависит от прав Windows. Реальные сессии, роли и сетевой rate limit CLI не реализует.
