## Запуск в Windows PowerShell

Нужен Python 3 с установленной стандартной библиотекой. Для прототипа и тестов не требуется устанавливать сторонние пакеты.

```powershell
Set-Location 'C:\Users\Администратор\Desktop\Skolkovo'
$env:HMAC_SECRET = 'demo-secret-k3'
python .\10_tests.py
```

demo-secret-k3 — открытый демонстрационный ключ выданных данных, не секрет настоящего сервиса. Программа читает его через окружение; ключ не записывается в аудит.

Ожидаемый итог проверок: 17 проверок, 15 успешных и 2 expected failures из-за исходных противоречий. Подробности — в 03_тесты.md и evidence/test_results.json. Надпись OK (expected failures=2) не означает, что исходные T3-1 и T3-2 прошли.

## Консольный запрос

```powershell
python .\04_прототип.py .\examples\qr_001.json
python .\04_прототип.py .\examples\qr_003.json
```

При сегодняшней дате оба исторических QR корректно дадут QR_EXPIRED. Тесты используют часы на дату учебного набора через конструктор, а обычный запуск не предоставляет настройки для обхода TTL или принудительного ответа шлюза.

Поля JSON: qr_id, receipt_id, base_amount, tip_pct, idempotency_key. action=pay создаёт и сразу подтверждает платёж, как исходный прототип. action=create создаёт CREATED и возвращает confirm_token. Действия confirm, cancel и status используют payment_id; для confirm обязателен полученный confirm_token. Это разные шаги заданного жизненного цикла.

Нормальный последовательный запуск после получения актуального QR:

1. Отправить create с новым ключом.
2. Передать полученный payment_id и confirm_token в confirm либо payment_id в cancel.
3. При таймауте запросить status для того же payment_id, не создавать новую оплату.

## Выходные файлы

- payments_state.sqlite3 — локальное служебное состояние: платежи, ключи повторов и аудит. SQLite входит в Python и не требует отдельного сервера.
- payments_out.csv — семь колонок по исходному шаблону, одна строка на платёж; статус обновляется.
- audit_out.jsonl — события аудита без карточных реквизитов и токенов.
- evidence — протоколы проверок и контроль исходных файлов.
- output — оформленные материалы защиты.

HTTP-коды в JSON поясняют проектный контракт. Программа является CLI, а не веб-сервером. Регистрация, роли, генерация QR, четыре экрана и отчётность спроектированы в документах; CLI демонстрирует оплату. Реальные деньги не переводятся.
